ENG-12 | NeonBackup.gs | New file lease (NB_LEASE_KEY_ in CacheService; nbLeaseClaim_(who, ttlS, waitMs, force) under a short script lock, nbLeaseRelease_(token)). runNeonBackup_ claims it (600 s TTL, force after a 60 s wait) before opening the store and releases it in `finally`; its step-5 scrub reuses the token. nbScrubPending_ returns 'busy' while a backup holds it (ids stay queued, picked up by the backup's own scrub step) and runs up to NB_SCRUB_MAX_PASSES_ passes. A killed run leaves the lease to expire (5-10 min), which only delays a scrub.
ENG-2 | DqeSilenceWatch.gs | When no new dept crosses the threshold but alerted streaks are still dark, the outcome is `SILENT (already alerted) N dept(s) still dark as of <date> -- Dept (Nd since X, N queue calls)` (+ watched count), not `ok`; the `ok` text names under-threshold streaks being watched. No new email (one alert per episode stays the rule).
ENG-1 | Alerts.gs, Digest.gs, SystemHealth.gs | installAlertTrigger_ / installDigestTriggers delete only the daily / cadence triggers (new alertsDeleteDailyTriggers_ / digestDeleteCadenceTriggers_); a pending one-shot retry survives a reinstall. Uninstall still removes both. SystemHealth: a `DEFERRED` outcome older than HEALTH_DEFERRED_MAX_MS_ (3 h; retries are hourly) turns its out-alerts / out-digest-<cadence> row warn with "RETRY LOST".
ENG-13 | CompanyOverview.gs | computeOverviewPipelineFreshness_ skips a DQE success row whose note names a built date more than OVERVIEW_FRESH_BUILD_MAX_LAG_DAYS_ (5) days before its own timestamp (pure ovPipelineNoteDateIso_ reads `callDate=M/D/YYYY` and a leading Date.toDateString(); ovPipelineRowIsFreshBuild_).
